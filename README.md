# IRL — Flutter client (v0)

The player-facing app: home hub, one playable district (Digital), a
scenario/chat screen, and an outcome screen with an animated score ring.
Talks to the `irl-backend` API for scenario content and scoring — no local
game logic beyond the visuals.

## First-time setup

This folder ships with `pubspec.yaml` and `lib/` only — no `android/`,
`ios/`, or `web/` platform folders, since those need to be generated by
your local Flutter SDK (they're version-specific and shouldn't be
hand-authored). From inside this folder:

```bash
flutter create . --project-name irl_app --platforms=web,ios,android
flutter pub get
```

That adds the platform runners around the existing `lib/` and
`pubspec.yaml` without touching either.

## Running it

Make sure `irl-backend` is running on `localhost:4000` first, then:

```bash
flutter run -d chrome
```

If your backend runs somewhere other than `localhost:4000` (e.g. once you
deploy it), point the app at it without touching code:

```bash
flutter run -d chrome --dart-define=API_BASE_URL=https://your-backend-url
```

## Structure

```
lib/
  main.dart              entrypoint, theme + state provider setup
  theme/
    app_theme.dart        shell design tokens (dark background, violet accent)
    district_theme.dart   per-district accent/gradient/type — the "worlds" layer
  models/
    scenario.dart          plain fromJson models matching the backend contract
  services/
    api_service.dart       the two HTTP calls (today / respond)
  state/
    app_state.dart         in-memory cumulative Savvy/Integrity/Street Smarts
  screens/
    home_screen.dart       hub: stats + district list
    scenario_screen.dart   fetches today's scenario, renders chat + choices
    outcome_screen.dart    animated score ring + stat breakdown
  widgets/
    stat_pill.dart, district_card.dart, persona_bubble.dart,
    choice_tile.dart, score_ring.dart
```

## Design notes

- Only the **Digital District** is playable — the other three render as
  locked placeholder cards on the hub, matching the "demo the vision, ship
  the wedge" plan.
- Each `DistrictTheme` carries its own accent color, background gradient,
  and heading font, so a district's scenario/outcome screens feel like a
  distinct world without the app shell (nav, stat pills, layout) ever
  changing — that's what keeps it from feeling cluttered as more districts
  unlock later.
- No local persistence yet — stats reset on reload. The backend's flat
  results log is the source of truth for retention while validating.

## A note on this build

This was written by hand in an environment without the Flutter SDK
available, so it hasn't been compiled here the way `irl-backend` was
smoke-tested end-to-end. The code follows standard, current Flutter/Dart
patterns throughout, but run `flutter analyze` right after `pub get` as a
first check, before diving into `flutter run`.
